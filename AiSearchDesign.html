Engineering Blueprint

Azure AI Search Implementation

The Azure AI Search index stores searchable content and applies semantic ranking and natural language understanding to deliver results based on the underlying meaning and intent of a query rather than just simple keyword matches.

1. Ingestion Pipeline: Scheduled Sync from release of Documentation Portal to Search Index

Adinsure documentation is maintained in .md format. Currently you can browse it on the documentation portal. Upon portal release, files are pushed to Azure Blob Storage. The Scheduled Indexer Execution configuration allows the Indexer to run at defined intervals (e.g., daily), automatically syncing new and modified content to the search index.

2. Enrichment Engine: Text to Vectors

The enrichment pipeline transforms raw Markdown fragments into semantic coordinate representations, structuring documentation for high-precision retrieval during the RAG workflow.

A

Document Cracking

Extracts Markdown text bodies and identifies technical metadata (URI, file path, last modified) for delta-sync change tracking.

B

Token Chunking

Segments long documents into chunks based on semantic boundaries to preserve context.

C

Vector Generation

Calls the text-embedding-3-large model to generate embeddings, capturing the semantic essence of the data and stores it in vector databases for efficient retrieval.

3. The AI Engine: From Question to Answer

Step A: Finding the Best Matches

When you ask a question, the search engine looks for document sections with the most similar meaning. It uses a high-performance ranking system to score every piece of data.

Step B: Building the AI Response

The most relevant parts of your documents are selected and combined with clear instructions for the AI. This ensures the AI stays focused on your data, providing accurate answers based only on your official documentation.

Official Data
The best pieces from your documents
AI Instructions
"Only use the document facts above."
Final Result
A reliable, fact-based answer
By grounding the AI in actual documents, we prevent it from "guessing" or providing incorrect information.

4. Secure Backend Access

We created a private backend application that manages all communication. This acts as a security gatekeeper, making sure only authorized users can interact with our AI search tool. It can also be used to monitor and control how the system is used.
